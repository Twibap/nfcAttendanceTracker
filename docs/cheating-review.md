# 치팅 가능성과 오프라인 기록 검토

검토일: 2026-10-14 / 상태: 문서 기반 위협 분석 초안. 실제 공격 재현이나 실기기 검증은 아직 수행하지 않았다.

## 대상과 보안 목표

현장에 고정된 NFC 태그를 개인 스마트폰이 읽고, 네트워크가 없으면 기기에 저장했다가 연결 복구 후 서버로 보내는 구조를 검토한다. 사용자 경험 목표는 앱을 미리 열거나 추가 터치하지 않고 태그만 하는 것이다. 이후 사용자가 앱 방식과 공통 지원 범위 내 진행을 선택했으므로 현재 기본 흐름은 앱 활성 상태의 읽기로 정한다. 플랫폼별 제한은 [서비스 지원 범위](platform-support.md)를 따른다.

검증 대상을 다음처럼 구분한다.

- 태그가 등록된 정품인지.
- 제출한 증거가 조작되지 않았으며 이미 사용한 증거가 아닌지.
- 등록 사용자·기기의 요청인지.
- 주장한 시각에 기기가 현장에 있었는지.
- 실제로 해당 사용자가 현장에 있었는지.

앞의 검증을 통과했다고 뒤의 사실까지 증명되는 것은 아니다. NFC 태그와 등록 기기만으로 모든 대리 출석을 방지한다고 주장하지 않는다.

## 위협과 완화 후보

아래 완화책은 후보이며, 목표 사용자 동작과 충돌하는 항목은 승인 없이 필수 기능으로 채택하지 않는다. 포그라운드 앱을 사용해도 NDEF·URL·UID만으로 정품 태그·실제 발생 시각·본인 현장 여부가 증명되는 것은 아니다. 백그라운드 링크 진입은 편의 경로이며 그 자체가 출석 증거가 아니다.

| 위협 | 발생 경로 | 완화 후보 | 잔여 위험·제약 |
| --- | --- | --- | --- |
| 고정 URL 공유 | 현장에서 읽은 링크를 다른 사람에게 보내거나 저장해 원격 요청한다. | 고정 URL·태그 UID만으로 확정하지 않고 검증 가능한 동적 증거를 사용한다. | 로그인한 사용자도 공유 링크를 제출할 수 있다. 로그인만으로 현장 여부를 알 수 없다. |
| 태그 복제·교체 | 태그 내용을 복사하거나 현장의 태그를 공격자 태그로 바꾼다. | 비밀키 기반 정품 인증, 등록 태그 목록, 태그별 키 관리와 교체 절차를 검토한다. | UID만으로 정품을 판정하지 않는다. 정품 인증이 태그의 설치 위치를 증명하지는 않는다. |
| 태그 반출 | 정품 태그를 떼어 가져가 다른 장소에서 읽는다. | 물리적 고정, 봉인, 훼손 감지, 설치·점검 이력을 검토한다. | 일반 카드 자체는 위치를 알지 못한다. 정품 태그도 반출될 수 있다. |
| 사용한 증거 재제출 | 같은 인증 메시지로 여러 번 출석하거나 여러 계정이 사용한다. | 서버에서 태그 증거의 단일 사용을 원자적으로 처리하고 업로드 재시도는 멱등 처리한다. | 정상 재시도와 다른 계정의 재사용을 구분해야 한다. 동시에 들어온 요청도 검증해야 한다. |
| 미사용 증거 수집·공유 | 미리 읽은 동적 메시지를 저장하거나 원격 사용자에게 보내 처음 사용하게 한다. | 온라인 실시간 challenge-response 인증, 추가 현장 증거를 검토한다. | 동적 MAC·카운터와 등록 기기 서명만으로 원격 제출을 막지 못한다. 전용 앱의 추가 NFC 통신은 무조작 목표와 충돌할 수 있다. |
| 실시간 중계 | 현장 협력자가 태그 통신·증거를 원격 사용자에게 전달한다. | 짧은 인증 수명, 독립된 현장 증거, 관리형 단말기 등 복합 검증을 검토한다. | 실시간 상호인증도 지연이 짧은 중계를 무조건 막지 않는다. 근거리 NFC 통신 자체가 사람의 위치 증명은 아니다. |
| 휴대폰 대여·다중 계정 | 다른 사람의 등록 휴대폰을 대신 태그하거나 한 기기로 여러 계정을 처리한다. | 기기 등록·변경 이력, 계정 전환 제한, 필요 시 생체 인증을 검토한다. | 기기 등록만으로 소지자가 본인인지 알 수 없다. 매번 생체 인증은 추가 동작이며 별도 선택이 필요하다. |
| 기기 시각 조작·소급 제출 | 휴대폰 시각을 바꾸거나 이전 증거를 과거 시각으로 제출한다. | 발생 주장 시각·서버 수신 시각 분리, 이상 탐지, 추가 신뢰 시각 증거, 검토 대기 처리를 검토한다. | 서버는 인터넷 단절 중 실제 발생 시각을 직접 관찰하지 못한다. 기기 서명만으로 시각의 진실성을 증명하지 못한다. |
| 로컬 기록 변조·삭제 | 앱 저장소를 수정하거나 퇴근 기록만 삭제해 더 오래 근무한 것처럼 만든다. | 보호된 기기 키로 기록 묶음을 서명하고 순서·연속성을 검토한다. 앱 저장소 보호와 삭제 감지도 검토한다. | 루팅·탈옥·기기 초기화 등에 대한 보장 범위를 정해야 한다. 아직 업로드되지 않은 마지막 기록의 삭제는 연속성 검증만으로 발견되지 않을 수 있다. |
| 동기화 순서 악용·거짓 거부 | 다른 사람의 최신 카운터가 먼저 업로드된 후 정상 오프라인 기록이 늦게 도착한다. | 태그 증거 사용 이력, 카운터 순서, 업로드 지연 정책을 함께 설계한다. | 단순히 ‘현재 최대 카운터 이하 전부 거부’하면 정상 오프라인 기록도 거부된다. 낮은 카운터를 허용하면 오래된 미사용 증거 위험이 커진다. |
| 출퇴근 상태 혼동 | 연속 태그·업로드 재시도·누락으로 출근이 퇴근으로 바뀐다. | 이벤트 종류와 중복 판정을 명확히 하고 누락·불일치는 검토 대상으로 처리한다. | 자동 번갈아 처리만으로 사용자의 의도를 확정하기 어렵다. 앱에서 종류 선택을 요구하면 목표 경험이 달라진다. |
| 인증 키 유출 | 공통 태그 인증 키를 앱에 넣거나 관리 키가 노출된다. | 태그별 키 분리, 서버의 제한된 검증 권한, 보호된 키 보관, 폐기·교체 절차를 검토한다. | 앱에 태그의 대칭 비밀키를 배포하면 인증 증거 위조 위험이 커진다. 오프라인에서 검증이 어렵다고 공통 키를 배포하지 않는다. |

위 표는 예상 공격 시나리오에 대한 설계 분석이며, 구현에서 검증된 방어 결과가 아니다.

## 동적 보안 태그의 정확한 보장 범위

NXP NTAG 424 DNA의 SDM/SUN은 표준 NDEF 읽기에 인증 데이터를 담아 서버가 정품 태그에서 생성된 메시지를 검증하도록 지원한다. 적절히 구성한 MAC과 읽기 카운터는 메시지 변조와 재사용 탐지에 사용할 수 있다.

하지만 태그에서 생성한 인증 데이터는 로그인 사용자·등록 기기·신뢰 가능한 실제 시각에 자동으로 결합되지 않는다. 나중에 등록 기기가 그 데이터를 서명해도, 그 기기가 태그를 현장에서 직접 읽었다는 사실이 새로 증명되지는 않는다.

NXP 데이터시트 §9.3은 공격자가 메시지를 미리 읽어 저장하고 나중에 검증자에게 제출할 수 있다고 명시한다. 이전에 본 카운터 및 순서에 맞지 않는 카운터를 거부하는 완화책을 제시하지만, 이 위험을 수용할 수 없다면 challenge-response 상호인증과 전용 앱을 사용하도록 안내한다.

이 안내와 다수 사용자의 지연 오프라인 업로드 사이에는 검증 정책상의 충돌이 있다. 구현 전에 허용 지연과 메시지 순서 처리 규칙을 정해야 한다. 단순 카운터 완화책을 완전한 재전송 방지 또는 현장·시각 증명으로 설명하지 않는다.

## 오프라인 기록 정책에서 결정할 사항

1. **상태 구분:** 기기 저장 완료, 업로드 완료, 서버 검증 완료, 검토 대기를 구분한다.
2. **시각 구분:** 기기가 주장한 발생 시각과 서버 수신 시각을 별도 저장한다. 신뢰 가능한 추가 근거 없이 발생 시각을 확정하지 않는다.
3. **정상 지연과 공격 구분:** 미사용 증거의 오래된 제출과 정상 오프라인 기록을 구분할 근거 및 허용 지연을 정한다. 수동 태그의 카운터만으로 구분 가능하다고 가정하지 않는다.
4. **중복·동시성:** 업로드 재시도는 같은 결과를 반환하고, 다른 이벤트나 계정이 같은 태그 증거를 동시에 소비하지 못하도록 한다.
5. **충돌 처리:** 다른 기기의 업로드로 카운터 순서가 뒤집힌 경우 기록을 조용히 폐기하거나 자동 확정하지 않는다. 검토 또는 거부 정책을 사전에 정한다.
6. **기록 유실:** 앱 제거, 로그아웃, 기기 변경, 저장 공간 부족 및 강제 종료 시 미전송 기록의 복구·알림 범위를 정한다.
7. **최종 정정:** 관리자가 보정한 기록은 원본 이벤트와 분리하고, 정정 사유·작성자·시각을 남기는 방안을 검토한다.

인터넷 단절 중 저장을 지원하는 것은 확정 요구사항이다. 오프라인 기록을 출석·근무·초과근무로 자동 확정하는 신뢰 수준과 규칙은 아직 확정되지 않았다.

# 세션 인수인계

## 기록 이력

- 2026-10-14 / v3: 영문 저장소 이름을 `nfc-attendance-tracker`로 정하고, 사용자 요청에 따라 현재 문서 4개를 로컬 최초 커밋 대상으로 정리했다.
- 2026-10-14 / v2: 사용자 선택에 따라 설치 앱 방식을 확정하고 공통 기본 흐름·플랫폼별 지원 범위·후속 구현 단위를 기록했다.
- 2026-10-14 / v1: 사용자 요구사항과 플랫폼 제약, 치팅 가능성 및 오프라인 검증 과제를 최초 기록했다.

## 완료된 변경

- `README.md`: 앱 방식 선택과 공통 기본 범위를 반영했다. 추가 터치 없는 태그 목표는 유지하며, 공통 보장과 구분했다. 최소 기술 검증 앱의 구현 순서를 남겼다.
- `docs/platform-support.md`: iOS·Android의 기능별 지원 조건, 편의 진입 경로, 보장 제외 기능, 설정 및 실기기 검증 항목을 별도로 기록했다.
- `docs/cheating-review.md`: 앱 활성 상태의 공통 흐름을 반영하고 링크 진입 자체를 출석 증거로 간주하지 않는 원칙을 연결했다. 기존 위협·잔여 위험을 유지했다.
- `docs/session-handoff.md`: 완료 내용, 미해결 과제와 다음 첫 작업을 기록했다.

문서 기반 정합성·링크 경로·변경 범위를 점검했다. 앱·서버 코드는 없으며 실제 NFC 동작이나 치팅 방어 테스트를 통과했다고 주장하지 않는다. v1·v2는 인수인계 문서로 기록했다. v3의 현재 문서 4개는 사용자 요청에 따른 로컬 최초 커밋 대상이며, 실제 커밋 여부와 식별자는 Git 이력에서 확인한다. 영문 저장소 이름은 `nfc-attendance-tracker`로 정했다.

Advisor 판단: 이번 작업은 앱 방식과 공통·플랫폼 지원 명세 확정으로 마무리한다. 기술 스택·인증·출퇴근 판정까지 결정된 것으로 확대하지 않는다. 다음 구현은 최소 기술 검증 앱으로 시작한다.

## 미해결 과제

- P1: 기술 검증 앱의 프레임워크·빌드·실기기 환경을 선정하고 최소 OS·지원 기종을 확인한다. 현재 기본 흐름은 앱 활성 상태의 읽기이며 무조작·잠금 상태 읽기는 보장하지 않는다.
- P1: 태그 인증과 사용자·기기 인증을 선정하고, 원격 증거 공유·대리 출석에 대해 보장할 수준을 정한다.
- P1: 오프라인 발생 시각의 신뢰 수준, 업로드 허용 지연 및 카운터 순서 충돌 처리 규칙을 정한다.
- P2: 출근·퇴근 구분, 결석 일정, 휴게·자정 경계·누락 기록 및 초과근무 승인 규칙을 정한다.
- P2: 개인 NFC 카드와 현장 리더기 방식의 도입 여부를 정한다.

## 다음 첫 작업

> README.md, docs/platform-support.md, docs/cheating-review.md를 읽는다. 설치 앱 방식을 다시 확인하지 말고, 공통 기능을 구현할 기술과 개발·실기기 환경을 선정한다. 양쪽 플랫폼에서 동일 NDEF 태그 읽기 → 로컬 기록 저장 → 종료·재실행 후 보존 → 연결 복구 시 시험 서버 전송 → 중복 방지를 확인하는 최소 기술 검증 앱을 만든다. 실제 조작 수와 플랫폼별 제한을 기록한다. 시험 태그 기록을 실제 출석으로 확정하지 않고, 인증·오프라인 시각 정책과 출퇴근 규칙이 정해지면 운영 MVP로 확장한다.

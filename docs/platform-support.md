# 플랫폼별 서비스 지원 범위

기준일: 2026-10-14 / 상태: 공식 문서에 근거한 개발 범위. 앱 구현과 실기기 검증은 아직 수행하지 않았다.

## 결정과 표 읽는 법

사용자는 iPhone·Android 설치 앱 방식과 플랫폼 공통 지원 범위 내 진행을 선택했다. 원래 목표인 ‘앱을 미리 열거나 추가 터치하지 않고 태그만 하기’는 유지하되, 현재 공통 지원으로 약속하지 않는다.

- **공통 기본:** 양쪽 플랫폼에서 제공할 기본 기능. 구현 완료를 의미하지 않는다.
- **조건부 편의 기능:** 기종·OS·설정에 따라 추가할 수 있는 기능. 기본 흐름을 대체하지 않는다.
- **별도 검증:** API 가능성과 실제 서비스 동작·보안 보장을 구분하고 검증 후 채택한다.
- **공통 보장 제외:** 현재 설계에서 모든 지원 기기에 제공한다고 약속하지 않는 동작.

지원 기기의 최소 조건은 앱 설치·초기 등록, 해당 플랫폼의 NFC 읽기 가능 여부 확인, 현장 태그와의 호환성 확인이다. 최소 OS 버전과 최종 기종 목록은 기술 검증 앱을 빌드하고 실제 기기로 확인한 후 확정한다. 백그라운드 읽기의 iPhone XS 기준을 모든 앱 내 NFC 읽기의 최소 기종으로 혼동하지 않는다.

## 기능별 지원표

| 기능 | iPhone / iOS | Android | 서비스 범위 |
| --- | --- | --- | --- |
| 앱 활성 상태에서 NDEF 읽기 | Core NFC 읽기 세션 사용. NFC 읽기 지원 검사와 앱 권한 설정 필요. | NFC 하드웨어·활성 상태를 검사하고 앱의 태그 처리 사용. | 공통 기본. 동일 태그로 양쪽 실기기 확인 필요. |
| 읽기 시작 동작 | 시스템 읽기 화면이 표시된다. 앱에서 세션을 시작해야 한다. | 앱 활성 상태의 태그 처리를 구현한다. | 공통 기본. 앱 진입 후 자동 시작 가능 여부와 실제 터치 수는 별도 검증. |
| 앱을 미리 열지 않은 URL 태그 진입 | iPhone XS 이후 백그라운드 읽기에서 알림 터치 후 앱으로 전달. Universal Links와 Associated Domains 필요. | Android 16부터 HTTP/HTTPS 태그는 `ACTION_VIEW`. Android 17부터 링크 열기 알림 터치 필요. App Links로 앱 연결 가능. | 조건부 편의 기능. 앱 미실행 상태에서 태그만으로 기록하는 공통 기능으로 설명하지 않는다. |
| Android 전용 MIME·기술 태그 진입 | 같은 방식의 백그라운드 진입을 공통 제공하지 않는다. | 태그 dispatch와 앱 필터로 처리 가능하나 버전·설정·앱 상태 영향을 확인해야 한다. | 확장 후보. 공통 기본에서 제외. |
| 화면 꺼짐·잠금 상태에서 태그만으로 기록 | 일반 앱 읽기의 공통 보장 없음. 백그라운드 전달에도 기기 상태·잠금 해제 조건이 있다. | 일반적으로 잠금 해제 상태에서 태그 탐색. 기종·설정 차이 있음. | 공통 보장 제외. 교통카드처럼 동작한다고 약속하지 않는다. |
| NFC 미지원·읽기 불가 | 읽기 가능 여부를 확인하고 기록 성공으로 처리하지 않는다. | 하드웨어 존재와 NFC 활성 여부를 확인하고 기록 성공으로 처리하지 않는다. | 공통 기본. NFC가 불가능한 기기의 현장 출석 대체 수단은 이번 범위에서 미정. |
| 오프라인 태그 기록 | 읽기와 로컬 저장을 구현한다. 초기 등록·필요 설정은 사전 완료 전제. | 동일 원칙으로 구현한다. | 공통 기본. 서버 검증 전에는 임시 기록. |
| 앱 재실행 후 대기 기록 보존 | 지속 가능한 로컬 저장 사용. | 동일 원칙으로 구현한다. | 공통 기본. 앱 제거·데이터 삭제까지 보존한다고 약속하지 않는다. |
| 앱 실행 중 연결 복구 후 전송 | 대기 기록 전송·재시도. | 대기 기록 전송·재시도. | 공통 기본. 네트워크 연결 표시는 서버 도달 성공과 다르므로 실패 시 기록 유지. |
| 앱을 닫은 상태에서 전송 | OS가 허용하는 백그라운드 작업·전송을 활용할 수 있으나 실행 시각은 제한된다. | 네트워크 조건을 둔 WorkManager 작업 등을 활용할 수 있으나 실행은 스케줄링과 시스템 조건 영향을 받는다. | 조건부 보완 기능. 연결 복구 즉시 업로드나 고정 완료 시간을 공통 보장하지 않는다. |
| 강제 종료·최초 미실행·재부팅 | 세션·앱 실행 및 동기화 복구를 조건별 실기기 확인한다. | Android 17 NFC dispatch는 stopped 상태 앱에 전달되지 않는다. 재부팅·강제 종료와 대기 작업 복구를 구분해 확인한다. | 별도 검증. 미전송 기록은 다음 정상 앱 실행에서 재시도하는 기본 경로 제공. |
| 서버의 중복 처리·상태 조회 | 같은 이벤트 ID와 서버 판정 계약을 사용한다. | 동일 계약을 사용한다. | 공통 기본. 중복 제출과 정상 재시도를 구분. |
| 정품 태그 인증·challenge-response | Core NFC의 태그별 통신 기능을 사용할 수 있으나 태그·프로토콜·권한에 따른 검증 필요. | 태그 기술별 통신 기능을 사용할 수 있으나 태그·프로토콜·기종에 따른 검증 필요. | 보안 방식 선정 후 별도 검증. NDEF 읽기 성공만으로 인증 완료로 간주하지 않는다. |
| 결석·근무·초과근무 산출 | 서버 판정 결과를 표시하는 앱 기능으로 제공. | 동일 기능으로 제공. | 일정·휴게·승인·누락 규칙을 확정한 뒤 구현. 플랫폼별 다른 판정 규칙을 만들지 않는다. |
| Wallet·교통카드와 같은 카드 에뮬레이션 | 일반 태그 읽기와 다른 기능·자격 요건 검토 필요. | 카드 에뮬레이션은 일반 태그 읽기와 다른 설계다. | 이번 공통 기본에서 제외. 현장 리더기 방식도 별도 선택 대상. |

## 공통 앱 기록 흐름

1. 초기 사용자·기기 등록과 NFC 가능 여부 확인.
2. 앱 활성 상태에서 읽기 세션 시작 → 현장 태그 읽기.
3. 이벤트와 태그 증거를 로컬에 저장하고 저장 결과 표시.
4. 연결 가능 시 서버 전송 시도. 실패하면 전송 대기 상태로 보존.
5. 다음 앱 실행·연결 복구·동기화 동작에서 재시도. 지원되는 백그라운드 실행 기회에서도 같은 대기 기록을 처리.
6. 서버 판정에 따라 검증 완료·검토 대기·거부 결과 표시. 로컬 저장 성공을 출석 확정으로 표시하지 않음.

읽기 취소·시간 초과·잘못된 태그는 기록 성공으로 표시하지 않는다. 별도 태그 접촉 없이 URL이나 앱 링크만 전달받은 요청은 현장 출석 증거로 확정하지 않는다. 실제 태그 접촉, 정품 인증, 본인 현장 여부의 보장 범위는 [치팅 검토](cheating-review.md)를 따른다.

## 플랫폼 설정과 운영 조건

| 플랫폼 | 구현에서 확인할 설정 | 현재 상태 |
| --- | --- | --- |
| iOS | Core NFC capability·entitlement, `NFCReaderUsageDescription`, 읽기 지원 검사. 편의 진입을 추가할 때 Associated Domains·Universal Links 설정. | 미설정·미검증 |
| Android | NFC 권한·하드웨어 검사·활성 상태 안내·태그 처리. URL 진입을 추가할 때 App Links 설정. Android 17 대상 조건에 따른 `DISPATCH_NFC_MESSAGE` 보호와 NFC 앱 허용 설정 확인. | 미설정·미검증 |
| 공통 | 태그 발급·고정·등록, 계정·기기 등록, 로컬 대기 기록, 서버의 멱등 처리·검증·오류 판정. | 미구현 |

외부 앱·스토어 배포와 도메인 연결은 아직 수행하지 않았다. iOS NFC는 실제 iPhone에서, Android NFC는 NFC 하드웨어가 있는 실제 기기에서 검증한다. 에뮬레이터·화면 데모만으로 NFC 지원을 검증했다고 기록하지 않는다.

# NFC 출석·출퇴근 확인 시스템

영문 저장소 이름: **`nfc-attendance-tracker`**. NFC 기반 출석·출퇴근 기록 서비스를 나타낸다.

현장에 고정된 NFC 태그에 개인 스마트폰을 대면 출석·출근·퇴근 이벤트를 기록하고, 인터넷 연결 시 서버에 업로드하는 서비스를 구상한다.

**iPhone·Android에 설치하는 앱 방식으로 진행한다.** 양쪽 플랫폼에서 지원하는 공통 기능을 기본 범위로 삼고, 플랫폼 전용 기능은 별도로 구분한다. 현재 앱 방식과 지원 명세를 확정하는 단계이며, 앱·서버 코드는 아직 구현하지 않았다.

## 사용자 요구사항

| 항목 | 요구사항 | 상태 |
| --- | --- | --- |
| 현장 확인 | 출석 현장에 NFC 카드 또는 태그를 고정하고 스마트폰으로 읽는다. | 확정 |
| 제공 방식 | iPhone·Android에 설치하는 앱으로 제공하고, 플랫폼 공통 지원 범위에서 진행한다. | 확정 |
| 사용자 동작 | 서비스 앱을 미리 열지 않고, **알림 터치 등 추가 조작 없이 태그만으로 기록**하는 것을 목표로 한다. | 목표 유지, 공통 보장 범위에서는 제외 |
| 오프라인 | 인터넷이 없는 현장에서도 기록을 저장하고, 연결 복구 후 서버에 업로드할 수 있어야 한다. | 확정 |
| 기록 대상 | 출석·출근·퇴근 이벤트를 저장하고, 일정·근무 규칙에 따라 결석과 초과근무를 산출한다. | 상세 규칙 미정 |
| 부정 출석 방지 | 태그 복제, 증거 공유, 대리 태그, 시간 조작 및 오프라인 동기화 과정의 치팅 가능성을 검토한다. | 별도 검토 문서 작성 |
| 개인 NFC 카드 | 개인 카드를 현장 리더기에 태그하는 방식도 초기 구상에 포함된다. | 도입 여부 미정 |

사용자의 원래 선호는 추가 터치 없는 태그 경험이다. 이후 사용자가 앱 방식과 공통 지원 범위 내 진행을 선택했으므로, 현재 기본 흐름은 앱 활성 상태의 NFC 읽기로 정의한다. 원래 목표는 유지하되 달성했다고 설명하지 않는다.

## 확정한 공통 지원 범위

지원 대상은 NFC 읽기가 가능한 iPhone과 Android 스마트폰이다. 최소 OS 버전과 지원 기종 목록은 기술 검증 앱의 빌드·실기기 확인 후 확정한다.

- 앱 설치와 초기 사용자·기기 등록을 전제로 한다.
- **앱이 활성화된 상태에서 NFC 읽기 세션을 시작하고 현장 태그를 읽는 흐름**을 기본으로 한다. 읽기 시작에 별도 버튼이 반드시 필요한지, 앱 진입 후 자동 시작할 수 있는지는 구현·실기기 검증 대상이다.
- 태그에서 읽은 데이터와 이벤트를 로컬에 먼저 저장한다. 인터넷 없이 저장하고 앱 재실행 후에도 전송 대기 기록을 유지한다.
- 온라인에서는 전송을 시도하고, 오프라인 기록은 연결 복구 후 앱 활성화·재실행 또는 동기화 동작에서 다시 전송한다. OS가 허용하는 백그라운드 동기화는 이를 보완한다.
- 전송 재시도 시 이벤트 중복을 막고, 저장·전송 대기·서버 검증·검토 대기 상태를 구분한다.
- 공통 태그 읽기의 출발점은 NDEF 형식이다. NDEF 읽기 자체를 출석 인증으로 취급하지 않으며, 최종 보안 태그와 인증 방식은 치팅 검증 후 결정한다.

앱 미실행 상태에서 무조작 기록, 화면 꺼짐·잠금 상태의 상시 읽기, 네트워크 복구 직후의 즉시 백그라운드 업로드는 공통 보장 범위에 포함하지 않는다. 개인 NFC 카드·현장 리더기·Wallet 방식도 이번 기본 범위에 포함하지 않는다.

플랫폼별 기능·조건·제한·검증 상태는 [플랫폼별 서비스 지원 범위](docs/platform-support.md)에 기록했다. 위 목록은 개발 범위이며 실제로 구현·검증된 기능 목록은 아니다.

## 추가 터치 없는 태그 경험과 기술 제약

다음은 일반 NDEF URL을 읽는 방식에 대한 공식 문서 기준이며, 모든 NFC 구현 방식에 대한 단정이 아니다.

| 플랫폼 | 확인된 일반 태그 읽기 동작 | 목표와의 차이 |
| --- | --- | --- |
| iPhone XS 이후 | 백그라운드에서 태그를 감지하지만, 알림을 누른 뒤 앱 또는 웹으로 전달한다. 기기 사용 상태 등의 조건이 있고 잠금 해제가 필요할 수 있다. | 추가 터치 없이 기록하는 목표를 충족하지 못한다. |
| Android | 일반적으로 잠금 해제 상태에서 태그를 읽고 해당 앱의 화면으로 전달한다. HTTP/HTTPS 태그는 Android 16부터 `ACTION_VIEW`로 처리하며, Android 17부터 링크 열기 알림을 눌러야 한다. | OS·태그 형식·설정에 따른 차이가 있어 공통 지원을 보장할 수 없다. |

따라서 **고정된 수동 NFC 태그 + 일반 URL 연결 방식만으로 iPhone·Android 전체에서 추가 조작 없는 자동 기록을 보장할 수 없다.** 대중교통 결제의 사용자 경험을 일반 태그 읽기에 그대로 적용할 수 있다고 가정하지 않는다.

기본 흐름은 앱 설치·초기 등록과 앱 활성 상태의 읽기를 전제로 한다. 최소 OS·지원 기종과 플랫폼별 편의 진입 경로는 실기기 검증 후 정한다. Android 전용 태그 처리나 현장 리더기와 휴대폰 자격증명 방식은 확장 후보이며, 검증 전에는 채택하거나 가능하다고 확정하지 않는다. 현장 리더기 도입은 원래의 고정 카드 방식과 달라 사용자 선택이 필요하다.

## 기록·동기화 설계 원칙

앱 방식의 공통 기록 흐름은 다음과 같다. 인증 프로토콜과 저장 기술은 아직 결정하지 않았다.

1. 초기 등록에서 개인 계정과 사용할 기기를 연결한다.
2. 현장 태그를 읽으면 태그 증거와 출석·출근·퇴근 이벤트를 수집한다.
3. 오프라인일 때는 기기에 전송 대기 기록을 보관한다. 저장 완료와 서버 검증 완료를 구분한다.
4. 인터넷 연결 복구 후 앱 실행 중 전송을 재시도한다. OS가 허용하는 백그라운드 실행에서도 전송을 시도하되 즉시 실행을 보장하지 않는다. 서버에서 인증·중복·순서·시각 관련 검증을 수행한다.
5. 검증을 통과한 기록만 확정하며, 증거가 부족하거나 충돌하는 기록은 검토 대기로 구분한다.

현장에 놓은 수동 NFC 태그 자체가 서버로 전송하는 것은 아니다. 이 방식의 읽기·저장·전송 주체는 스마트폰이다. 개인 NFC 카드를 쓰는 별도 방식에서는 전원이 있는 현장 리더기 등 읽기 장치가 필요하며, 수동 카드 두 장만으로는 서로 읽을 수 없다.

오프라인 기록에는 최소한 이벤트 ID, 사용자·등록 기기 식별자, 현장 식별자, 이벤트 종류, 태그 증거, 기기가 주장하는 발생 시각, 서버 수신 시각을 구분해 보관하는 방안을 검토한다. **기기 시각과 업로드 시각 중 어느 것도 그 자체로 실제 태그 시각을 증명하지 않는다.**

출근·퇴근을 단순히 태그 횟수에 따라 번갈아 처리할지, 별도 태그로 구분할지 등은 미정이다. 결석은 예정 일정과 유효한 출석 기록을 대조하여 판단해야 한다. 근무·초과근무 계산은 휴게, 야간·자정 경계, 누락 기록 및 승인 규칙을 확정한 후 구현한다.

## 부정 출석 방지

일반 고정 URL 또는 태그 UID만으로 현장 출석을 확정하지 않는다. 동적 인증 태그는 후보지만, 정품 태그 인증과 사람이 현장에 있다는 증명은 서로 다르다.

위협, 완화책, 잔여 위험 및 오프라인 검증 과제는 [치팅 가능성 검토](docs/cheating-review.md)에 별도로 기록했다. 태그·앱·서버 구현 전에 이 문서의 반증 시나리오를 검증한다.

## 다음 구현·검증

첫 구현 단위는 양쪽 플랫폼에서 동일한 태그를 읽고 로컬 기록을 보존·동기화하는 최소 기술 검증 앱이다. 프레임워크와 개발 도구는 착수 시 선정하며, 인증 정책이 미정인 동안 시험 기록을 실제 출석으로 확정하지 않는다.

1. iPhone·Android에서 동일한 NDEF 태그 읽기를 확인하고 실제 조작 수를 기록한다.
2. 오프라인 저장 후 앱 종료·재실행 시 기록이 보존되는지 확인한다.
3. 연결 복구 후 시험 서버 전송·재시도·중복 방지를 확인한다.
4. 플랫폼 지원표의 조건별 시나리오를 실기기에서 확인하고 최소 OS·기종 범위를 확정한다.
5. 태그·사용자·기기 인증, 오프라인 시각·지연·충돌 정책 및 출퇴근 판정 규칙을 확정한 뒤 운영 MVP로 확장한다.
